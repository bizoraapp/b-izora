# Bizora — translation guide (English / French)

Bizora is fully bilingual. Most shop owners in Cameroon use it in **French**, so a missing or clumsy French string is a real defect, not a cosmetic one. Read this before adding or changing any text a user can see.

## 1. How it works

All of it lives in `index.html`:

| Piece | What it does |
|---|---|
| `I18N_DICT = { en:{…}, fr:{…} }` | One flat key → string dictionary per language. About 1,350 keys each in 4.3.8. **Both sides must always have exactly the same keys** (`node tests/tools/i18n_parity.js index.html`). |
| `currentLang()` | `'fr'` or `'en'`, read from `S.obj('prefs').lang`. |
| `t(key)` | The current language, then English, then the key itself. A missing French string silently shows English, so parity is checked by tools, not by looking. |
| `tf(key, {name:value})` | `t()` plus `{name}` placeholders (implemented by `_revFill`). Use it for any sentence containing a number, name or amount. **Never build sentences by concatenating fragments**: French word order differs. |
| `tOpt(key, fallback)` | For keys assembled at runtime (`'entity_'+type`). An unknown key returns the fallback instead of showing a raw key. |
| `data-i18n="key"` | Static markup: `applyI18n()` replaces the element's `textContent`. |
| `data-i18n-ph="key"` / `data-i18n-title="key"` | Placeholder / tooltip for static markup. |
| `applyI18n()` | Runs at startup and on every language switch. It only scans the DOM that exists **at that moment**. |
| `setLang(lang)` | Saves the choice, runs `applyI18n()`, then re-runs the current page's loader so JS-rendered content redraws. |

## 2. Rules

1. **Every new visible string gets an EN and an FR entry in the same change.** The post-edit hook blocks a parity mismatch.
2. **Static markup:** use `data-i18n` and put the English text inside the element too (so it reads sensibly before `applyI18n()` runs).
3. **Anything rendered from JavaScript** (template strings, `innerHTML`, toasts, `confirm2()` messages, table headers, modal titles): call `t()`/`tf()` **at render time**.
   - **Do not use `data-i18n-title` inside dynamic templates.** `applyI18n()` never runs on markup created later, so the tooltip stays in English forever. This happened in the SMS reminder button and was caught before release (see `BUG_HISTORY.md`, i18n-01).
4. **Stored values are never translated.** Role keys, permission keys, statuses, payment-method values (`'cash'`, `'mobile-money'`…), reasons, audit and activity text (`logAuditEvent`, `log`) stay in canonical English. Translate only where they are **displayed**, through a label function, for example:
   - payment methods: `_payMethodLabel()` / `_payMethodDisplay()` (stored `'cash'` → "Cash" / "Comptant"; missing → "Not recorded" / "Non enregistré");
   - `_payMethodEn()` produces the English label used inside audit text.

   Translating a stored value breaks filters, reports, backups and every record saved in the other language.
5. **User-entered data is never translated** (customer and product names, notes, addresses).
6. **Key names:** reuse an existing key when the meaning is identical; otherwise follow the prefix of the area (`toast_`, `val_`, `lbl_`, `btn_`, `th_`, `pos_`, `inv_`, `fin_`, `exp_`, `set_`, `bkp_`, `rpt_`, `pa_`, `lic_`, `perm_`, `js_txt_`, `js_hd_`, `js_val_`, `js_lbl_`…). Never rename or delete an existing key: old code paths and tests may use it.
7. **Check French at 360 px.** French is often 20–30 % longer. Buttons must wrap or shrink, never clip (the POS button "Terminer la Vente et Imprimer le Reçu" is a known clipping case, backlog BZ-015).
8. **Out of scope by design:**
   - the hidden Developer Suite (about 13 English-only toasts);
   - `offline.html` (a separate page with no access to the dictionary).

## 3. French typography (follow exactly)

The dictionary already uses these consistently; new strings must match.

| Rule | Write | In the source |
|---|---|---|
| Non-breaking space **before** `: ; ? !` | `Payé par : Comptant` | `'Payé par : Comptant'` (139 uses) |
| Typographic apostrophe | `l’acompte`, `d’échéance` | `'l’acompte'` (315 uses). Never a straight `'` inside French text (it also breaks the JS string) |
| Guillemets with non-breaking spaces | `« Non enregistré »` | `'« Non enregistré »'` |
| Money | `FCFA 12,500` in both languages | Always `cur(n)` (and `fmtExact` / `fmtQty` for bare numbers). Never format amounts by hand and don't change the separators: `parseFloat` is wrapped app-wide to strip thousands commas, so a French-style separator would break input parsing |
| Capitals | Sentence case for messages; Title Case only where the English UI already uses it for that label family | — |

**Known defect, deliberately not fixed yet:** `_pdfEsc()` (PDF receipts) only keeps Latin-1 characters, so the curly apostrophe `’` prints as `?` in PDF receipts. Do not "fix" it inside an unrelated change. It needs its own small, approved change (map `’`→`'` and ` `→space before the Latin-1 filter).

## 5. Traps

- **CSV exports:** report table headers (`renderDynReport` `<th>`) double as CSV column names. Translating them changes the export schema. If they are ever translated, keep the CSV header canonical through a separate `data-csv` attribute ("Option B"); never translate them directly.
- **`confirm2()` shows plain text** (`textContent`): HTML tags in a translated message print literally.
- **Interpolation tokens must match in both languages:** `{count}`, `{error}`, `{name}`… A token missing from the French string silently drops the value.
- **Escaping:** a French string containing `'` must use `’`, not a straight apostrophe, or the whole script block fails to parse. The syntax hook catches the failure; the rule prevents it.
- An i18n scan tool from the 4.2.x work excluded keys matching `^perm_` more broadly than intended. If you write a scan for untranslated strings, list exclusions explicitly.

## 6. Validation for any text change

1. `node tests/tools/i18n_parity.js index.html` → EN = FR, 0 missing.
2. Switch to FR in the app and open every screen you touched, including dynamic content (toasts, modals, receipts, PDF, WhatsApp text).
3. 360 px width in French: no clipping or horizontal scroll.
4. Confirm no stored value changed language (look at a saved record and an audit entry).
